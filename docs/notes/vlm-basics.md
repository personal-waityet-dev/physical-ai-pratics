## 이론 목표 및 이해

### 1. 이미지가 토큰이 되는 과정

> 패치화, 위치 임베딩, 해상도·패치 크기와 토큰 수의 관계(224px / 패치 14 → 256 토큰)

**ViT** ([2010.11929](https://arxiv.org/abs/2010.11929)), §3.1만

- 패치 임베딩이 "픽셀 패치의 선형 사영"이라는 것은 어떤 `Conv2d` 하나와 같은 연산인가? LLM의 토큰 임베딩(lookup)과는 무엇이 다른가?
  - Conv2d 합성곱: Σ (채널 c, 창 안의 행 i, 열 j) W[d, c, i, j] · x[c, i, j]
  - 패치 임베딩 (P * P * C) → D: Σ (채널 c, 창 안의 행 i, 열 j) W[d, c, i, j] · x[c, i, j], i,j = 0~(P-1), c : C, d : D
  - 패치 임베딩 = 입력 채널 C, 출력 채널 D, 창 크기 P, 이동 간격 P인 Conv2d
  - (Claude) 합성곱은 모든 창 위치에서 같은 W를 쓴다 = 모든 패치에 같은 사영 행렬을 곱한다.
  - 픽셀 패치(P * P * C) 를 D 차원 임베딩 벡터로 사영하는 것. 토큰 임베딩은 입력 토큰에 대한 룩업 테이블 인덱스를 임베딩한다. 픽셀 패치는, 단순 토큰 룩업 테이블과 다르게, 이미 픽셀 패치 자체가 정보를 담고 있으며, P * P * C 의 다차원 벡터에 대한 선형 사영이므로, 토큰 임베딩이 룩업 테이블에 없는 새로운 인덱스-토큰-이 새로 주어지면 해당 토큰을 포함한 데이터로 적합해야 하는 것과 다르게, 새로운 이미지 패치에서도 기존 적합 사영이 동작한다.
- 위치 임베딩은 GPT-2의 무엇과 같고, RoPE 계열과는 무엇이 다른가?
  - 실험에서는 패치의 스캔 순서에 따른 절대값 위치 임베딩을 사용한다. GPT-2의 시퀀스 내에서의 절대값 위치 임베딩과 동일하다.
  - 절대 위치를 사용하며 학습 가중치에 따른 임베딩을 수행하여 입력에서 패치 임베딩에 더해진다.
  - RoPE는 고정 함수를 사용하며, 모든 어텐션 층의 쿼리·키에 적용된다(Claude 수정, 원래 "어텐션 층에서 처리된다"). 위치를 임베딩에 적용하지 않고, 절대 위치에 따른 각도함수를 어텐션 계산에 사용하여, 상대 위치가 사용된다.

- (Claude) 덧붙임: 학습 해상도보다 큰 이미지를 넣어 토큰이 많아지면 연산이 되나? 잘려서 따로 처리되나?
  - 트랜스포머 층의 가중치(쿼리·키·값 사영, MLP)는 토큰마다 똑같이 곱해지는 D×D 모양이라 토큰 개수와 무관하다. 어텐션은 토큰 N개면 N×N 점수표를 만들 뿐이라, 길이가 늘면 비용이 N²으로 커질 뿐 계산은 된다.
  - 모양이 길이에 묶인 부품은 학습된 위치 표(256×D) 하나다. 더 긴 패치 임베딩에 그대로 더하면 모양이 안 맞아 에러가 난다. 모델이 알아서 잘라 주지 않는다.
  - 배치의 서로 다른 항목끼리는 어텐션이 없다. 그래서 고해상도를 다루는 길은 둘이다.
    1. 위치 표를 보간해 한 시퀀스로 넣는다: 전체에 어텐션이 걸리지만 비용이 N²으로 커진다.
    2. 이미지를 조각으로 잘라 조각마다 따로 인코딩한다(LLaVA-NeXT, SmolVLM): 인코더 안에서는 조각끼리 못 보므로 전체를 줄인 축소본 한 장을 함께 넣고, 조각 사이 관계는 이어 붙인 토큰 전체를 보는 언어 모델에서 다룬다.

### 2. 대조학습

> CLIP(softmax InfoNCE) vs SigLIP(sigmoid loss, 배치 크기 의존성 차이)

**CLIP** ([2103.00020](https://arxiv.org/abs/2103.00020)) → **SigLIP** ([2303.15343](https://arxiv.org/abs/2303.15343))

- softmax(InfoNCE) 손실은 배치 안에서 무엇을 보고, 왜 배치 크기에 민감해지나? 임베딩 모델 학습에서 쓰던 in-batch negatives와 연결해 본다.
  - 배치 안에서 조건 (텍스트 0~n | 이미지 i, 이미지 0~n | 텍스트 j)의 정규화된 소프트맥스 분포를 보고 크로스엔트로피로 손실을 결정한다.
  - 배치 크기에 따라 분포 자체가 영향을 받게 되어, n쌍의 배치인 경우 (positive 1, negative n-1)^2의 정답 분포가 되고, 이에 따라 배치에 민감해진다.
- sigmoid 손실은 무엇을 바꾸나? 배치를 여러 장치에 나눌 때 무엇이 쉬워지나?
  - 시그모이드 손실은 전체 분포를 봐야 하는 소프트맥스+크로스엔트로피가 아닌, 개별 이미지/텍스트 임베딩에 대해 개별 연관도를 시그모이드로 결정한다.
  - 의미적으로 모델의 적합 방향(이미지 i의 라벨 텍스트 j와의 연관만 존재하고, 나머지 텍스트와의 연관은 없다. 역으로 텍스트 → 이미지도 동일)은 동일하지만, 계산적으로는 전체 데이터에서 단일 라벨을 결정하는 소프트맥스 방식에서 멀티라벨 결정 방식으로 변경되었다(다만 "정답" 라벨이 하나일 뿐).
  - 전체 분포가 아닌 개별 이미지-텍스트 쌍의 연관을 보게 되므로, 각 이미지-텍스트 쌍에 대한 손실 계산 시 배치 전체 분포를 알 필요가 없어, 여러 장치에 데이터가 분산되어도 계산을 단말에서 분산 처리한 후 최종 손실만 합산하면 된다.
- SigLIP은 학습 가능한 온도 t와 편향 b를 두고, b를 **−10**으로 초기화한다. 배치 안의 positive:negative 쌍 비율을 생각하면 왜 그렇게 큰 음수에서 시작하나?
  - 손실 함수가 개별 이미지/텍스트 연관을 보게 되는데, 데이터 대부분에서 이미지/텍스트 대부분의 연관이 negative인 것에 따른 모델의 초기 편향 및 부정 편향 과적합을 조정하기 위한 편향 b를 두고, negative 방향 값으로 초기화한다.

## 용어 정리 (Claude)

### "패딩"의 세 가지 뜻

| 패딩 | 어디서 | 왜 |
|---|---|---|
| 배치 패딩 | 길이가 다른 시퀀스를 한 배치로 묶을 때 | 텐서를 직사각형으로 만들려고. 채운 자리는 어텐션 마스크로 가린다. 모델의 길이 제약과는 무관하다 |
| 합성곱 패딩 | 이미지 경계 밖 | 창이 경계를 넘어가게 하려고. 실행 1 예측 Q2(384px)가 이 경우 |
| 텍스트 최대 길이 패딩 | SigLIP 텍스트 입력 | 보통은 마스크와 정해진 토큰 위치(CLS, EOS) 덕분에 결과에 영향이 없다. SigLIP은 마스크 없이 고정 길이(16)로 학습하고 출력 시퀀스의 마지막 칸(패딩 자리)을 출력 벡터로 써서, 패딩 방식이 결과를 바꾼다. 영향의 크기는 실행 2에서 관측 |

### 온도 t (대조학습의 점수 배율)

- 출력 벡터를 길이 1로 정규화하면 내적(코사인)이 −1~1에 갇혀, 정답은 거의 1·오답은 거의 0 같은 확신 있는 확률을 시그모이드·소프트맥스로 표현할 수 없다. t는 점수 범위를 −t~t로 넓힌다(점수 = t·코사인 + b).
- t는 모든 쌍에 똑같이 곱하는 스칼라라 순위는 바꾸지 않는다. zero-shot 1등 클래스와 recall@k는 t·b와 무관하고 확률 값만 바뀐다.
- 그래도 학습에서 중요한 이유는 늘린 값이 비선형 함수(시그모이드, 소프트맥스)를 통과하기 때문이다. t가 "어느 정도의 코사인 차이를 확실한 차이로 볼지"를 정해 손실과 기울기의 크기·분포를 바꾼다. 소프트맥스에서는 t가 클수록 가장 헷갈리는 오답에 기울기가 몰린다. LLM 샘플링 온도와 같은 원리다.
- 정규화로 방향(의미)과 크기(확신)를 분리해, 벡터는 의미만 배우고 확신은 t 하나가 맡는다. 적당한 확신 정도는 학습 중 바뀌므로 t도 학습한다(SigLIP: 시작 10 → 사전학습 후 111.5).

### SDPA (`torch.nn.functional.scaled_dot_product_attention`)

- eager와 같은 식 softmax(QKᵀ/√d + 마스크)·V를 계산하는 함수 하나. 장치·자료형·마스크를 보고 구현을 고른다: CUDA에서는 FlashAttention·메모리 효율 어텐션·cuDNN, Mac에서는 MPS 자체 구현, 마지막 대안은 식 그대로(math, eager와 같음).
- 키·값을 조각 단위로 읽으며 쿼리 행마다 최댓값 m, 지수 합 ℓ, 누적 출력 o만 이어서 갱신한다(최댓값이 바뀌면 이전 누적에 e^(m−m')를 곱해 맞춤). N×N 표 없이 정확히 같은 결과를 내고 메모리는 O(N²) → O(N·d). 메모리 왕복이 줄어 빠르기도 하다.
- 실측(Mac MPS, torch 2.14, 헤드 16·헤드 차원 72): 점수표가 4GB인 N=8192에서도 메모리 증가 없음. N=4096에서 SDPA 21ms, eager 152ms. SigLIP 최대 메모리가 N에 비례한 이유가 이것과 층마다 해제되는 것이다.
- 주의: 어텐션 가중치를 돌려주지 않으므로 헤드별 패턴을 보려면 eager로 불러온다(P02·P15). 임의 모양 마스크(prefix-LM, 실행 5)는 다른 구현으로 넘어갈 수 있다. eager와 출력은 더하는 순서 때문에 반올림 수준으로 다르다.
