## 읽기 — 각 자료에서 답을 찾을 질문

전부 정독하기보다 아래 질문에 답하는 것을 목표로 읽는다. 답은 `docs/notes/vlm-basics.md`에 쓴다.

**ViT** ([2010.11929](https://arxiv.org/abs/2010.11929)), §3.1만
- 패치 임베딩이 "픽셀 패치의 선형 사영"이라는 것은 어떤 `Conv2d` 하나와 같은 연산인가? LLM의 토큰 임베딩(lookup)과는 무엇이 다른가?
- 위치 임베딩은 GPT-2의 무엇과 같고, RoPE 계열과는 무엇이 다른가?

**CLIP** ([2103.00020](https://arxiv.org/abs/2103.00020)) → **SigLIP** ([2303.15343](https://arxiv.org/abs/2303.15343))
- softmax(InfoNCE) 손실은 배치 안에서 무엇을 보고, 왜 배치 크기에 민감해지나? 임베딩 모델 학습에서 쓰던 in-batch negatives와 연결해 본다.
- sigmoid 손실은 무엇을 바꾸나? 배치를 여러 장치에 나눌 때 무엇이 쉬워지나?
- SigLIP은 학습 가능한 온도 t와 편향 b를 두고, b를 **−10**으로 초기화한다. 배치 안의 positive:negative 쌍 비율을 생각하면 왜 그렇게 큰 음수에서 시작하나?

**LLaVA** ([2304.08485](https://arxiv.org/abs/2304.08485)) → **PaliGemma** ([2407.07726](https://arxiv.org/abs/2407.07726))
- projector를 거친 이미지 토큰은 LM 입장에서 어떤 LLM 미세조정 기법과 가장 닮았나? (입력 앞에 학습된 벡터를 붙이는 계열)
- LLaVA 2단계에서 각 단계에 무엇을 얼리고 무엇을 학습하나? 왜 그 순서인가?
- PaliGemma의 prefix-LM mask에서 어떤 토큰들끼리 양방향으로 보나? T5·UniLM에서 본 것과 무엇이 같은가?

**DINOv2** ([2304.07193](https://arxiv.org/abs/2304.07193)) — 실행 3 직전에
- 이미지-텍스트 대조학습(SigLIP)과 자기지도 학습(DINOv2)은 각각 패치 특징에 무엇을 남기도록 압력을 주나?

## 실행별 — 먼저 예측하고, 그다음 확인한다

각 실행 전에 예측을 README에 먼저 적고, 실험 후 맞았는지·틀렸다면 왜인지를 쓴다.

### 실행 1 — 패치화

모델은 PaliGemma와 같은 비전 인코더인 SigLIP So400m/14를 쓴다: `google/siglip-so400m-patch14-224`(약 3.5GB, 게이팅 없음). 384 해상도에는 `-384` 체크포인트가 있다.

예측 질문:
1. 224px, 패치 14 → 토큰 몇 개? 384px는? 384는 14로 나누어떨어지지 않는다 — 남는 픽셀은 어떻게 되나?
2. 224 모델에 **512px** 이미지를 넣으면 모델의 어느 부분이 문제가 되나? LLM에서 학습 길이보다 긴 context를 넣을 때와 비교해 본다.

검증 기준:
- reshape/permute만으로 만든 패치에 모델의 패치 임베딩 가중치를 적용한 결과가 HF 모델의 패치 임베딩 출력과 일치한다(`allclose`, 허용 오차를 명시).
- 해상도별 토큰 수가 손 계산과 같다. 메모리·지연 측정은 측정 조건(장치, dtype, 배치, 워밍업 여부)을 함께 기록한다.

### 실행 2 — zero-shot·검색, softmax vs sigmoid

예측 질문:
1. SigLIP으로 zero-shot 분류를 할 때 클래스별 확률을 모두 더하면 1이 되나? 안 된다면 분류 결과를 어떻게 읽어야 하나?

관측(예측 대신):
- 인코더를 얼리고 작은 projection head를 학습할 때, 배치를 줄이면 softmax 손실과 sigmoid 손실 중 어느 쪽 성능(시험 recall)이 더 많이 떨어지나? 원래 예측 질문이었지만 관측으로 옮겼다(2026-10-21). 이 규모(배치 16–256, 학습 이미지 6000장)에서는 학습 속도, t·b 초기값, seed 흔들림이 배치 효과만큼 크게 작용해서 원리로 답이 정해지지 않는다. SigLIP 논문의 비교는 배치 512–1M, 본 예제 수십억 규모다. README에 이미 적은 예측은 그대로 두고, 결과는 이 관측으로 기록한다.
- 보통의 텍스트 인코더(BERT, CLIP)는 어텐션 마스크를 쓰고 출력에서 정해진 토큰 위치(CLS, EOS)를 골라 출력 벡터로 써서 패딩 길이와 무관하다. SigLIP은 출력 시퀀스의 맨 마지막 칸을 출력 벡터로 쓰고, 학습 때 항상 고정 길이(이 체크포인트는 16)로 패딩하고 가리지 않았다. 차이의 크기는 학습된 가중치에 달려 있어 원리로 예측할 수 없으므로, 관측해서 기록한다.
- 같은 문장(예: `'a photo of a cat'`)을 ① 처리기 기본값(패딩 없음) ② `padding="max_length"`(학습 때와 같음) ③ 길이가 다른 문장과 한 배치로 `padding="longest"`로 넣고, ②와 비교해 출력 벡터의 코사인 유사도, zero-shot 점수, 1등 클래스가 어떻게 달라지는지 본다. ③은 함께 묶는 문장을 바꿔 가며 같은 문장의 점수가 달라지는지도 본다.

검증 기준:
- recall@1/5/10을 이미지→텍스트, 텍스트→이미지 양방향으로, 평가 샘플 수와 함께 보고한다.
- 두 손실의 비교는 같은 데이터·같은 head 구조·같은 옵티마이저 설정에서 배치 크기만 바꾼다. 스텝 수를 고정하면 배치가 클수록 본 데이터가 많아지고, 에폭을 고정하면 배치가 클수록 업데이트 횟수가 적어져서, 어느 쪽이든 학습량 차이가 배치 효과에 섞인다. 그래서 각 설정을 **수렴할 때까지** 학습한다.
  - 멈출 시점은 **검증 분할**(`load_flickr8k("validation")`)의 recall로 정한다(조기 종료). 시험 분할로 정하지 않는다.
  - 설정마다 도달한 시험 recall과 **최고점에 도달한 스텝**을 함께 보고한다. 도달점과 도달까지의 학습량을 따로 읽기 위해서다.
  - 모든 설정에 같은 seed 목록(2–3개)을 쓰고, 평균과 범위를 보고한다. 차이가 seed 흔들림보다 큰지 판단하기 위해서다.
- 결과에는 무엇을 고정했는지(수렴 기준, patience, 학습률, t·b 초기값)를 함께 적는다.

방향 힌트: 인코더가 얼려져 있으면 인코더의 출력 벡터는 매번 다시 계산할 필요가 없다.

확장(선택): 대조학습에서 배치 크기는 "기울기 한 번에 쓰는 샘플 수"와 "정답 하나당 비교하는 오답 수"를 동시에 정한다. 학습 미니배치는 고정하고 손실을 계산할 때만 미니배치를 작은 묶음으로 나누면, 두 번째 역할만 바꿔 볼 수 있다.

### 실행 3 — SigLIP vs DINOv2 패치 특징 PCA

예측 질문:
1. 어느 모델의 패치 특징 PCA에서 물체 경계·부분이 더 또렷할까? 학습 목적으로 설명해 본다.
2. SigLIP 비전 모델에는 분류 토큰(CLS)이 없다. 그럼 이미지 전체 표현은 어디서 나오고, 패치 특징은 어디서 꺼내나?
3. DINOv2(`facebook/dinov2-small`)의 출력 토큰 수는 패치 수보다 많다. 왜 그런가?

환경 주의: torch 2.11에서는 MPS의 PCA 계열 분해(`linalg.qr`·`linalg.eigh`)가 실패했지만, 이 프로젝트의 torch 2.14에서는 동작한다(2026-10-14 확인). float64는 여전히 MPS에서 지원되지 않는다.

### 실행 4 — tiny VLM (projector만 학습)

예측 질문:
1. 두 모델 config에서 hidden size를 찾아, 2층 MLP projector의 학습 파라미터 수를 계산한다. 전체 파라미터 중 몇 %인가?
2. 이미지 1장 = 토큰 몇 개, 캡션 1개 = 토큰 몇 개인가? 이 비율에서 loss는 어느 토큰에만 걸어야 하나? LLM SFT의 무엇과 같은가?
3. 학습 전(무작위 projector) 캡션 loss는 이미지 없이 캡션만 넣은 loss와 비교하면 어떤 관계여야 하나?

검증 기준:
- 학습 전후 캡션 loss를 같은 평가 셋에서 비교한다.
- 학습에 쓰지 않은 이미지에서 생성한 캡션을 그대로 싣는다(골라낸 예시가 아니라 처음 N장).
- "이미지 없이 캡션만" 기준선 대비 loss가 내려갔는지 확인한다. 이게 이미지 정보를 실제로 쓰고 있다는 증거다.

방향 힌트: 비전 인코더가 얼려져 있으면 이미지 특징을 미리 계산해 두는 편이 Mac에서 훨씬 빠르다.

### 실행 5 — causal vs prefix-LM mask

예측 질문:
1. SmolLM2는 causal로 사전학습됐다. 여기에 prefix-LM mask를 씌우면 무엇이 어긋나나? PaliGemma는 이 문제를 어떻게 피했나?
2. 공정한 비교를 위해 무엇을 고정해야 하나?

검증 기준:
- 두 mask 행렬을 그림으로 나란히 보여주고, 어느 위치가 다른지 표시한다.
- 같은 조건에서 학습 곡선·평가 loss를 비교하고, 차이가 예측과 맞는지 쓴다.
